# Календарь звонков


[![hexlet-check](https://github.com/danilaKazimir/ai-for-developers-project-386/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/danilaKazimir/ai-for-developers-project-386/actions)

Разработайте совместно с ИИ сервис для бронирования календаря

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers
Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Пользовательские сценарии

### Организатор

1. Открывает главную страницу и нажимает «Создать календарь».
2. Указывает своё имя, название и описание встреч, длительность, часовой пояс, доступные даты и интервалы времени.
3. Проверяет данные и создаёт календарь. Сервис разбивает интервалы на слоты выбранной длительности.
4. Получает публичную ссылку на страницу записи и отправляет её гостям.

### Гость

1. Открывает календарь по ссылке и видит описание встреч, длительность и часовой пояс.
2. Выбирает доступную дату и свободный слот.
3. Вводит имя, email для связи и необязательный комментарий.
4. Подтверждает запись и видит подтверждение с датой и временем встречи.

Забронированный слот становится недоступным другим гостям. Если при подтверждении слот уже занят, сервис предлагает выбрать другое время. Прошедшие слоты недоступны, данные других гостей не отображаются.

### Ограничения первой версии

- Нет авторизации, личных кабинетов и интеграций с внешними календарями.
- Один календарь — один организатор и одна длительность встреч. Календари независимы друг от друга.
- Доступность задаётся на конкретные даты; время отображается в часовом поясе календаря.
- После создания календарь нельзя редактировать. Отмена и перенос встреч не предусмотрены.
- Подтверждение отображается на экране; отправки писем и автоматического создания видеозвонков нет.

## Стек

- React, TypeScript, Vite и TanStack Query; HTTP-запросы через сгенерированный Fetch SDK.
- TypeSpec → OpenAPI 3.1 → Orval / datamodel-code-generator → TypeScript SDK / Pydantic 2.
- Python, FastAPI, SQLAlchemy asyncio, psycopg 3, PostgreSQL и Alembic.
- mise управляет версиями инструментов и задачами, uv — Python-зависимостями, npm — JS-зависимостями.

Сейчас реализована главная страница о сервисе: кнопки «Создать календарь»,
статичный пример страницы записи и три шага работы. Кнопки ведут на
`/calendars/new` — страницу «Функция в разработке» со ссылкой на главную.
Эти страницы доступны без запущенных API и PostgreSQL. Создание календарей,
генерация слотов и бронирование пока не реализованы.

Согласованные требования к главной странице и критерии приёмки:
[Issue #1](https://github.com/danilaKazimir/ai-for-developers-project-386/issues/1).

Страница проверки подключения удалена; страницы `/status` нет. Диагностический
API `GET /api/health`, его сгенерированный SDK и тесты сохранены. Сервер проверяет
PostgreSQL запросом `SELECT 1`: при доступной БД API возвращает `200`, при ошибке
подключения — `503` с публичным кодом `DATABASE_UNAVAILABLE`. Для проверки API и
интеграционных проверок требуется окружение, описанное в разделах ниже.

## Структура

```text
api/main.tsp                  # Источник API-контракта
api/generated/openapi.yaml    # Сгенерированный OpenAPI 3.1
backend/app/                  # Приложение FastAPI, настройки, async-сессии
backend/app/generated/        # Сгенерированные транспортные модели Pydantic
backend/migrations/           # Миграции Alembic
backend/tests/                # Тесты API, контракта и PostgreSQL
frontend/src/                 # React-приложение
frontend/src/api/generated/   # Сгенерированный Fetch SDK и Query-хуки
frontend/e2e/                 # Браузерные тесты главной страницы на Playwright
scripts/generate.mjs          # Генерация и проверка её актуальности
mise.toml                     # Версии инструментов и общие задачи
compose.yaml                  # PostgreSQL для локальной разработки и CI
```

Один корневой [package.json](./package.json) содержит зависимости фронтенда и
JS-генераторов; один [pyproject.toml](./pyproject.toml) — зависимости бэкенда и
Python-инструментов. Lock-файлы сохранены в репозитории.

В `package.json` заданы временные `overrides` для исправленных версий `undici`
и `minimatch` в зависимостях генераторов и линтеров. При обновлении этих
инструментов проверьте, нужны ли переопределения; совместимость проверяется
общей задачей `check`.

## Установка

Предварительно установите [mise](https://mise.jdx.dev/getting-started.html) версии
2026.10.25 или новее и Docker с Compose v2. Docker Engine должен быть запущен.
Для команд из примеров требуется POSIX-оболочка (macOS/Linux).

В [mise.toml](./mise.toml) закреплены Python **3.13.18**, Node.js **24.22.2** и uv
**0.13.6**. PostgreSQL закреплён как `postgres:17.11-bookworm`.

```bash
git clone https://github.com/danilaKazimir/ai-for-developers-project-386.git
cd ai-for-developers-project-386
mise trust
mise install
cp .env.example .env
mise run setup
```

`setup` выполняет `uv sync --frozen`, `npm ci`, `mise run test:e2e:install`
и `mise run hooks:install`. Задача `test:e2e:install` скачивает версию Chromium,
закреплённую Playwright; на Linux она также может установить системные зависимости
браузера.
Задача `hooks:install` задаёт локальный `core.hooksPath=.githooks` для этого репозитория.
Виртуальное окружение `.venv`
создаётся с явным указанием Python из mise; загрузка другого Python через uv
отключена. Локальные переменные из `.env` подхватывает mise. Файл не коммитится.

В уже настроенном окружении после добавления Playwright установите зависимости
и браузер:

```bash
npm ci
mise run test:e2e:install
```

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_USER` | Пользователь PostgreSQL, по умолчанию `calendar` |
| `POSTGRES_PASSWORD` | Пароль локальной БД, по умолчанию `calendar` |
| `POSTGRES_DB` | База приложения, по умолчанию `calendar` |
| `POSTGRES_PORT` | Порт PostgreSQL на хосте, по умолчанию `5432` |
| `DATABASE_URL` | SQLAlchemy URL с драйвером `postgresql+psycopg` |
| `TEST_DATABASE_URL` | URL отдельной тестовой БД, имя должно оканчиваться на `_test` |
| `API_PROXY_TARGET` | Адрес FastAPI для прокси Vite, по умолчанию `http://127.0.0.1:8000` |

При изменении пользователя, пароля, имени БД или порта согласуйте оба URL с
настройками Compose. Значения `POSTGRES_*` применяются при первом создании volume;
изменение `.env` не меняет пользователей и базы в существующем volume.

## Использование

```bash
mise run db:up
mise run migrate
mise run dev
```

Фронтенд: <http://127.0.0.1:5173>. API: <http://127.0.0.1:8000/api/health>.
Интерактивная документация FastAPI: <http://127.0.0.1:8000/docs>.
Vite проксирует `/api` на бэкенд, поэтому локальному фронтенду не требуется CORS.
`Ctrl-C` останавливает оба процесса разработки; завершение одного процесса
останавливает второй. База продолжает работать.

```bash
mise run db:down
```

Эта команда останавливает PostgreSQL и сохраняет данные в volume. Бэкенд и миграции
используют асинхронный драйвер psycopg; на каждый запрос создаётся отдельная
`AsyncSession`, а при остановке API освобождается пул соединений.

## Генерация API

```bash
mise run generate
mise run generate:check
```

Источник истины — [TypeSpec](./api/main.tsp). Версия OpenAPI 3.1 задана явно в
[настройках эмиттера](./api/tspconfig.yaml). Orval и datamodel-code-generator
читают один и тот же [OpenAPI-документ](./api/generated/openapi.yaml).
Сгенерированные файлы сохраняются в Git и вручную не редактируются.

Проверка актуальности генерирует результаты во временном каталоге и сравнивает
сохранённые файлы побайтово, включая добавленные и удалённые файлы. Рабочие
сгенерированные файлы при проверке не перезаписываются. Ошибки HTTP передаются
из Fetch SDK в TanStack Query со статусом и телом ответа.

Обработчики, бизнес-логика и ORM-модели пишутся вручную. Любое изменение структуры
БД оформляется новой миграцией. Начальная миграция фиксирует историю Alembic и
пока не создаёт предметных таблиц.

## Проверки

Перед каждым коммитом Git-хук `pre-commit` запускает `mise run lint`: Ruff,
проверку форматирования Python и ESLint. Проверяется весь рабочий каталог,
включая изменения, ещё не добавленные в индекс; файлы автоматически не исправляются.
Ошибка блокирует коммит. Хук не требует PostgreSQL. Полная проверка остаётся
в `mise run check` и CI.

Для уже настроенного окружения подключите хук один раз:

```bash
mise run hooks:install
```

Проверки можно запустить вручную командой `mise run lint`.

Создайте отдельную тестовую БД. Для значений из `.env.example`:

```bash
mise run db:up
docker compose exec -T db createdb -U calendar calendar_test
mise run check
```

`createdb` выполняется один раз. Для повторных проверок достаточно `mise run check`.
Интеграционные тесты требуют `TEST_DATABASE_URL`, отличный от `DATABASE_URL`, и
имя БД с суффиксом `_test`. При отсутствии настройки тесты завершаются ошибкой,
а не пропускаются. Тест миграций выполняет downgrade/upgrade в тестовой БД.

Общая проверка включает Ruff, mypy, ESLint, TypeScript, pytest, Vitest, сборку Vite,
актуальность генерации, браузерные тесты Playwright и HTTP smoke-тест запуска.
Тесты проверяют реальные ответы
API по каноническому контракту, успешный запрос к PostgreSQL, параллельные запросы и отдельные сессии,
миграции и отсутствие деталей подключения в ответе `503`. Тесты SDK проверяют
успех, HTTP-ошибку в состоянии Query, не-JSON ответ и отмену запроса.

```bash
mise run test:unit         # Без PostgreSQL
mise run test:integration  # Только проверки PostgreSQL и миграций
mise run test:e2e          # Браузерные проверки без API и PostgreSQL
mise run test:smoke        # Запуск реальных FastAPI и Vite, проверка HTTP
```

Для `test:e2e` нужны установленные npm-зависимости и Chromium из
`mise run test:e2e:install`. Playwright сам запускает Vite на
`127.0.0.1:15174`; этот отдельный порт должен быть свободен. Тесты выполняются
в headless Chromium без запущенных API и PostgreSQL и проверяют переходы между
главной страницей и заглушкой `/calendars/new`, навигацию с клавиатуры и
расположение элементов на мобильном экране. Сценарии находятся в `frontend/e2e/`.

Для `test:smoke` нужны установленные зависимости, запущенный PostgreSQL
(`mise run db:up`) и существующая отдельная БД из `TEST_DATABASE_URL` с суффиксом
`_test`, отличная от `DATABASE_URL`. Создайте её командой `createdb` из примера
выше. Smoke-тест сам применяет миграции к тестовой БД, запускает Uvicorn без
перезагрузки на `127.0.0.1:18000` и Vite на `127.0.0.1:15173`; оба порта должны
быть свободны. На ожидание готовности отводится 30 секунд.

Проверка подтверждает успешный ответ `/api/health` напрямую и через прокси Vite,
а также выдачу HTML главной страницы. Она выполняется без браузера и не проверяет
исполнение React. После успеха, ошибки или прерывания smoke-тест завершает
запущенные им процессы; PostgreSQL продолжает работать, тестовая БД сохраняется.

Собственный [CI](./.github/workflows/check.yml) устанавливает инструменты из mise,
выполняет `mise run setup`, поднимает PostgreSQL через тот же Compose и запускает
`mise run check`. Учебный workflow Хекслета сохранён отдельно.

При реализации календарей потребуются дополнительные тесты создания календаря,
свободных слотов, бронирования и конкурентного конфликта `409` на PostgreSQL,
прошедших слотов, часовых поясов/DST и приватности данных гостей.
